# PHASE 2.1 TEMPORAL SCOPE DECISION v1

**Target:** Temporal operator necessity decision  
**Status:** `KILL TEMPORAL OPERATORS`  
**Execution authority:** `NONE`  
**Definitive Phase 2.1 experiment:** `NOT EXECUTED`  
**Branch:** `phase2-structural-transfer-20260910`

## 1. Decision

Temporal operators `BEFORE` and `AFTER` are **not necessary** to test the Phase 2.1 scientific question:

`A-derived relational abstraction -> reusable knowledge -> verified enablement/non-enablement prediction -> structural transfer to B`.

They are therefore removed from the Phase 2.1 candidate language rather than being retained behind an unstated role-to-Fact provenance mapping.

This is a prospective scientific scope decision. Historical protocol artifacts and historical results are not rewritten.

## 2. Necessity test

The Phase 2.1 transfer hypothesis requires four evidential links:

1. A produces relational experience from observable action/outcome structure.
2. SERL extracts reusable relational knowledge from A that is independent of B's task-specific labels.
3. The acquired knowledge is retrieved and applied to form a falsifiable `ENABLES(target)` or `NONENABLES(contrast,target)` prediction before the decisive intervention.
4. The prediction is causally verified and compared against K0 under structurally novel B tasks.

None of these logical links requires temporal predicates as a distinct candidate-grammar operator. The frozen relational vocabulary already contains observable causal/structural predicates including `BLOCKED`, `AVAILABLE`, `ACTION`, `INTERVENES`, `OBSERVED_EFFECT`, `ENABLES`, `NONENABLES`, and `SAME_LOCAL_CONTEXT`. The prospective consequence domain is independently frozen to the two verified consequences required by the transfer question.

Temporal ordering remains present in the **protocol event ledger and attribution procedure** wherever ordering is required to establish that retrieval/prediction preceded the decisive intervention. That procedural ordering is not the same thing as exposing `BEFORE`/`AFTER` as learnable candidate predicates. Removing candidate temporal operators therefore does not remove the chronology required for scientific attribution.

## 3. Why temporal operators do not uniquely identify structural transfer

Structural transfer is demonstrated by reuse of relational knowledge across A and structurally novel B, followed by verified causal consequence. A temporal relation between two candidate-bound action roles is neither necessary nor sufficient for that phenomenon:

- Necessary: no. A relational rule can be acquired, retrieved, predicted, and causally verified using the non-temporal observable predicates and the frozen consequence domain.
- Sufficient: no. Temporal ordering alone does not establish reusable abstraction, structural novelty, causal transfer, or attribution.
- Unique: no. The same A->B transfer claim can be expressed without a candidate-level temporal predicate while preserving the required causal verification chain.

Keeping `BEFORE`/`AFTER` would therefore expand the hypothesis language without adding a logically indispensable evidential link for the bounded Phase 2.1 question.

## 4. Scientific reason to kill rather than guess

The previous temporal grounding audit established that the mathematical operator is closed only after a provenance set has been selected, while the authoritative protocol did not specify the mapping from Action-sorted roles in `BEFORE(a,b)`/`AFTER(a,b)` to observable Facts and provenance sets.

Possible choices such as `ACTION(role)`, predicate-specific Facts, entity-wide Facts, typed role/predicate pairs, or composite candidate signatures are substantively different semantics. Choosing one merely to preserve an existing feature would change candidate validity, K_A acquisition, retrieval, prediction, and attribution.

Because the transfer hypothesis remains testable without the feature, there is no scientific justification for accepting that additional assumption in Phase 2.1.

## 5. Exact Phase 2.1 removal

The following candidate-level predicates are removed from the Phase 2.1 grammar:

- `BEFORE(Action, Action)`
- `AFTER(Action, Action)`

The following remain unchanged:

- `BLOCKED(Action)`
- `AVAILABLE(Action)`
- `ACTION(Action)`
- `INTERVENES(Action, Action)`
- `OBSERVED_EFFECT(Action, Effect)`
- `ENABLES(Action, Action)`
- `NONENABLES(Action, Action)`
- `SAME_LOCAL_CONTEXT(Action, Action)`

The Fact provenance/timestamp machinery needed solely to execute candidate `BEFORE`/`AFTER` predicates is not part of the Phase 2.1 candidate semantics. Event occurrence order remains part of the execution/attribution record wherever required by the parent protocol.

## 6. Effect on candidate enumeration

Candidate enumeration is performed over the amended Phase 2.1 grammar. The candidate search space is therefore strictly reduced by removing all atoms whose predicate is `BEFORE` or `AFTER`.

No replacement temporal atom, hidden temporal feature, special-case temporal tie-breaker, or benchmark-specific shortcut is introduced.

Canonicalization, duplicate elimination, deterministic ordering, role binding, candidate-size limits, and contradiction handling otherwise remain inherited from the authoritative prospective SERL specification.

## 7. Effect on K_A acquisition

K_A may contain only rules expressible in the amended non-temporal grammar. Rules whose validity or support depended on `BEFORE` or `AFTER` are no longer admissible Phase 2.1 knowledge.

The K_A acquisition gate remains otherwise unchanged: acquired knowledge must be nonempty, provenance-valid, cross-instance-supported, relational/non-episodic, label-invariant, B-independent, independently inspectable, and frozen before B exposure.

This does not forbid future ACE from learning temporal rules. It only prevents Phase 2.1 from using an unresolved temporal semantic boundary as evidence for structural transfer.

## 8. Effect on retrieval and prediction

Retrieval operates over the amended candidate language. There is no temporal predicate evaluation and therefore no role-to-Fact temporal selector or temporal provenance aggregation in the Phase 2.1 retrieval path.

Prediction remains exactly the prospective two-value consequence domain:

`ENABLES(target)` or `NONENABLES(contrast,target)`.

The prediction must still be formed before the decisive intervention and be falsifiable and subsequently verified under the existing attribution chain. Removing candidate temporal operators does not remove this procedural ordering requirement.

## 9. Effect on attribution

The attribution chain remains:

`retrieval -> application -> prediction -> intervention -> observed consequence -> verification -> attribution`.

Chronological precedence between these recorded events remains an execution-level requirement. The removal concerns only candidate-level `BEFORE`/`AFTER` atoms.

No attribution class, precedence ordering, K0-equivalent replay rule, or verification rule is relaxed by this decision.

## 10. Scientific hypothesis preservation

The primary Phase 2.1 hypothesis remains:

`C(B+ | K_A) < C(B+ | K_0)`

where K_A is acquired relational knowledge from A and B is structurally novel.

The required evidential interpretation remains:

`experience -> relational abstraction -> reusable knowledge -> structural transfer -> verified enablement/non-enablement consequence`.

Removing temporal candidate predicates changes the instrument's representational language, not the phenomenon being tested. The benchmark still asks whether relational knowledge learned from A can be reused to produce a verified causal consequence in novel B instances.

## 11. What capability is lost

Phase 2.1 will no longer test whether a learner can encode an explicit temporal relation as a candidate-level symbolic predicate whose operands require Fact-provenance grounding.

That is a real capability loss, but it is orthogonal to the bounded transfer question and was not uniquely required by it.

The loss is therefore acceptable for this instrument and should not be disguised as proof that temporal reasoning is unimportant to general intelligence.

## 12. Combined ACE implication

Temporal/event reasoning remains a first-class future ACE capability. The reusable architectural primitive should be broader than the removed benchmark predicate:

`typed event/entity grounding -> explicit provenance -> temporal relation -> causal/structural inference`.

Future ACE should support multiple temporal relations, explicit event references, provenance composition, uncertainty/partial order, interval or duration semantics where scientifically justified, and interaction with causal models. None of those broader semantics should be retrofitted into Phase 2.1 merely for completeness.

## 13. Non-execution and anti-optimization guarantees

No Phase 2.1 endpoint experiment, endpoint comparison, score, or expected-performance argument was used for this decision.

No task generation, threshold, seed, control, or benchmark outcome was changed based on predicted performance.

No toy cognitive machinery was added.

No historical experiment is reinterpreted as evidence for this decision.
